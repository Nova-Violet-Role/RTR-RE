## Defects (measured)

- D1 Rolling unbounded summary: each cycle merges old summary + new span with "keep all details" (compressor.py:135,531-536) and max_tokens 16000 (:353) but no summary size cap and no kept-message cap; keep is ratio-only (_find_keep_index :193-210). Long sessions grow the pinned first-message summary without bound.
- D2 Rolling type-blind: _messages_to_text truncates tool input at 500 chars and results at 1000 (:284-294) regardless of content type; base64/NDATA is summarized as text.
- D3 ACP inert and mis-bounded: enabled false; preserveRecentTokens 220000 > input limit 200000; protectedTools includes bash/read/grep/glob (acp.jsonc:13-26) so the largest outputs can never compress; reasoning.drop false (config default true, config.ts:410) leaves an unreclaimable floor; qualityGate layer1MinChars 4000 vs calibrated 200 (config.ts:430).
- D4 RTR cannot retrieve evicted session spans: index covers wiki files only; decompression re-exposes verbatim (ACP decompress) instead of typed retrieval. Restore injects up to 4000 chars with no relevance budget (memory.ts:117-118).
- D5 No shared Trigger/Target: Rolling TRIGGER 100000 / TARGET 40000 (README config table), ACP maxContextLimit 75% live vs 80% default, host preserve 25% usable. Three budgets, no derivation between them.
